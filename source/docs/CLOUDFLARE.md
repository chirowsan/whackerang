API (needs a token with Workers Scripts:Edit):
```
curl -X DELETE -H "Authorization: Bearer $TOKEN" \
  "https://api.cloudflare.com/client/v4/accounts/22a9493ab45eaf1f37232982e7196d42/workers/scripts/whackerang-relay?force=true"
```

Do **not** delete the workers.dev subdomain: the other Worker uses it. After deleting, the game keeps working over direct WebRTC (see "Turning it off").

`cd server/cf-relay && npx wrangler deploy` (needs `wrangler login`), or upload `worker.js` as a multipart module with metadata `{"main_module":"worker.js","compatibility_date":"2026-04-01","bindings":[{"type":"durable_object_namespace","name":"ROOMS","class_name":"Room"}]}`. ## Protocol (opaque, game-agnostic)
`wss://<worker>/r/<CODE>?role=host|guest` (CODE = 4-5 letters). The Worker checks the `Origin` header (must be `https://chirowsan.github.io`, `capacitor://localhost`, `https://localhost`, `http://localhost`, or `http(s)://localhost|127.0.0.1:<port>` for development), then forwards the socket to the Durable Object for that code.
* guest -> relay: `[kind u8][payload]`; the host receives `[guest id u8][kind u8][payload]`.
* host -> relay: `[guest bitmask u8][kind u8][payload]`; each guest in the mask receives `[kind u8][payload]`. One host broadcast is **one** inbound message however many guests there are (this is what keeps cost low).
* control (text JSON, generated by the relay): `ready`, `join`, `leave`, `hostgone`, `err` (`taken`, `nohost`, `full`). Text `ping` gets `pong` from the runtime auto-response (the object stays hibernated).

## Limits enforced by the relay
* 1 host + at most 3 guests per room (4 clients); further guests get `err full`. A second host on a live code gets `err taken`.
* Max frame 16 KiB (larger frames are dropped). Per-client token bucket: host 160 msgs/s, guest 90 msgs/s (the game sends about 15-30/s); a client that stays over the limit for ~300 messages is disconnected (4010).
* Idle timeout: the room is closed after 45 s without data when guests are present, 15 min for a host waiting alone (alarm every 30 s; the alarm is skipped when no sockets are open).
* No persistence: the Durable Object never uses `ctx.storage` except an alarm timestamp, keeps no history, and never logs frame contents (there are no `console.log` calls at all).
* Origin check as above; non-WebSocket requests get 426, unknown paths 404. Room codes are validated `[A-Z]{4,5}`.

## Free-plan budget (what to expect)
Free plan limits (Cloudflare published values): Workers 100,000 requests/day; Durable Objects 100,000 requests/day where **incoming WebSocket messages count 20:1** (outgoing do not), 13,000 GB-s duration/day, SQLite storage 5 GB (unused). These are **per account** and shared with `backyard-private-rooms`, which may already use some. If a limit is hit Cloudflare returns errors until 00:00 UTC; the game then simply stays on direct WebRTC (or shows the normal "couldn't connect" message on blocked networks). Nothing is ever billed on the Free plan.

Inbound messages per second = guests x input rate + host snapshot rate. Full rate: inputs 30/s, snapshots 20/s. **Low-bandwidth mode** (automatic when a link is relayed): inputs 15/s, snapshots 12/s (guests interpolate a bit more, input redundancy covers the lower rate).

| Room (5 min relayed play) | requests/room | Matches/day until 100k |
|---|---|---|
| 2 players, full rate | 750 | ~130 |
| 2 players, low-bandwidth | 405 | ~245 |
| 4 players, full rate | 1,650 | ~60 |
| 4 players, low-bandwidth | 855 | ~115 |

Duration is not the binding limit (a 5-minute active room is about 38 GB-s at 128 MB, so ~340 rooms/day). Only players whose direct connection fails use the relay, so real usage should be far below these numbers. These are calculations from the limits above, **not** measurements from the Cloudflare dashboard; check Workers > Metrics after real use.

## Turning it off
* Per device: `localStorage.setItem('whk.rly','off')`, or open the game with `?norelay=1` (and `?norelay=0` to re-enable). The game then behaves like v4.2 (direct WebRTC only).
* For everyone: ship a build with `RELAY_URL = ''` in `src/net/relay.js`, or delete the Worker (see above). Old builds then fail the relay step quickly and keep using direct WebRTC.
* Test builds can point at another relay with `window.__bbNet.rly = 'ws://...'` (used by `tools/net_relay43.mjs`).
